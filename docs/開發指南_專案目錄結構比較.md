## 1. 開發環境設置

### 必要工具

四專案共用同一套可攜式工具鏈，避免每個專案各自安裝一份：

| 工具 | 路徑/來源 | 用途 | 四專案共用？ |
|------|-----------|------|--------------|
| JDK 21 | `d:\ClaudeLab\android-dev\jdk-21.0.11+10` | Gradle 建置需要 | ✅ 共用 |
| Android SDK | `d:\ClaudeLab\android-dev\sdk` | 產出 Android APK，不需安裝 Android Studio | ✅ 共用 |
| electron / electron-builder | 各專案自己的 `node_modules`（`package.json` 內宣告） | 產出 Windows 桌面 EXE | ❌ **僅 myStock、TripleTown**，JournalApp、myLife 沒有 |

**為什麼 JournalApp、myLife 沒有 Electron？**
JournalApp 是既有 Web 系統（JournalCL）的「手機陪伴 App」，桌面使用者本來就直接用瀏覽器開 JournalCL 網站即可，不需要另外包一個桌面 EXE。myLife（天氣／交通／發票）是出門在外查的生活資訊，使用情境本身就在手機上，沒有桌面版需求。myStock（股票追蹤）、TripleTown（遊戲）則是獨立工具，沒有對應的既有網站可以取代桌面情境，所以才需要 Electron 讓使用者在 Windows 上雙擊執行、不必開瀏覽器。

### 環境設置步驟

四專案的開發啟動與打包指令一致（皆由各自的 `build-apk.cmd` / `package.json` scripts 提供）：

```bash
npm install          # 安裝相依套件
npm run dev          # 啟動 Vite dev server（區網手機可連，host: true）
npm run apk          # = build-apk.cmd：build → cap sync android → gradlew assembleDebug → release/*.apk
npm run exe          # 僅 myStock、TripleTown：build → electron-builder --win → release/*.exe
npm run verify       # 僅 myLife：執行 tools/ 底下的純函式直測腳本
```

**各專案 dev port 不同**（JournalApp 5175、myStock 5173、myLife 5176、TripleTown 5177），因為 `localStorage` 綁在 origin（含 port）上，共用 port 會讓不同專案共用同一份儲存。配置理由見 `APP_ARCHITECTURE.md`。

### 環境變數
不適用——四專案皆用 `.env.development`/`.env.production`（若有後端 API）或 Vite `base` 設定處理環境差異，非本文件比較重點，各專案的環境變數細節請見各自的 SRD/CLAUDE.md。（myLife 沒有後端也沒有 `.env`，API 金鑰由使用者在裝置上輸入、存於 Capacitor `Preferences`，不進 repo 也不進 APK。）

*（此章節為本文件核心內容，範本原無此標題層級，因應「多專案目錄結構比較」的主題新增；未省略範本原有任何章節）*

### 頂層目錄總表

| 目錄/檔案 | JournalApp | myStock | TripleTown | myLife | 用途 |
|-----------|:---:|:---:|:---:|:---:|------|
| `src/` | ✅ | ✅ | ✅ | ✅ | Vue 原始碼，`import` 引入、Vite 打包處理（檔名會被雜湊改名） |
| `public/` | ✅ | ✅ | ❌ | ❌ | 見下方「`public/` vs `src/` 的判斷準則」 |

| `android/` | ✅ | ✅ | ✅ | ✅ | Capacitor 產生的原生 Android 專案（`npx cap sync android` 產物+設定） |
| `build/` | ❌ | ✅ | ✅ | ❌ | electron-builder 的圖示/安裝程式設定來源（如 `icon.png`、TripleTown 另有 `installer.nsh` 自訂 NSIS 安裝程式） |
| `dist/` | ✅ | ✅ | ✅ | ✅ | `vite build` 輸出，供 `cap sync`／Electron 讀取，皆為建置產物、不進版控 |
| `release/` | ✅ | ✅ | ✅ | ✅ | 最終產出的 `.apk`／`.exe` 存放處，不進版控 |
| `docs/` | ✅ | ✅ | ✅ | ✅ | AISDLC 文件（JournalApp、TripleTown 有 `frd/`、`srd/`；myStock 另有 `prd/`；myLife 目前只有 `Operations_Guide.md`） |
| `openspec/` | ✅ | ✅ | ⚠️ 空目錄 | ✅ | OpenSpec 變更流程（`changes/`、`specs/`）。TripleTown 目前是空目錄，刻意保留供日後以 SDD（OpenSpec）開發 |
| `tools/` | ❌ | ❌ | ❌ | ✅ | myLife 專用：`npm run verify` 的直測腳本、打真實 API 的探測腳本與 `fixtures/` 樣本資料 |
| `.github/` | ❌ | ❌ | ✅ | ❌ | TripleTown 專用：GitHub Actions 部署網頁版到 GitHub Pages（`workflows/deploy.yml`） |
| 額外美術/資料來源 | `resources/`（icon.png/psd） | `assets/`、`data/`、`picts/`（icon/splash 來源、股票 CSV 資料、設計稿） | `art-reference/`（棋子美術設計稿 psd/jpg） | `assets/`（icon.png 與 psd 原稿） | 各專案依需求命名，非共同慣例 |

### `public/` vs `src/` 的判斷準則

四專案對「圖片該放 `src/` 還是 `public/`」的判斷一致，只是實際需求不同導致有無 `public/` 資料夾：

- **放 `src/`、用 `import` 引入**：檔案路徑在 build 時就已確定，Vite 會處理雜湊檔名與最佳化。
  例：TripleTown 的遊戲棋子圖（`src/picts/1.grass.png` 等）全部用 `import`，因此**完全不需要 `public/`**。
- **放 `public/`、用執行期組出來的字串路徑引用**：路徑在執行期才由變數決定（例如使用者選擇的頭像檔名），無法用 `import` 靜態引入，需要穩定、不被雜湊改名的網址。
  例：JournalApp／myStock 的頭像圖（`` `/avatars/${name}.svg` ``）、`index.html` 的 `<link rel="icon">` 直接寫死引用的 favicon 檔案。
- **兩者都不需要**：myLife 介面用 emoji 與文字呈現，沒有頭像、`index.html` 也沒有 favicon；地圖圖磚由 Leaflet 在執行期從外部網址載入，不放在專案內。因此 myLife 和 TripleTown 一樣**沒有 `public/`**。

  **檢查方式**：`public/` 底下的檔案在 `vite build` 時會被**原封不動**複製進 `dist/`；若專案有打包 Android/Electron 流程，`dist/` 內容又會被複製進下一次的 App 資產——這代表 `public/` 是「最終一定會進到 App 本體」的內容，只適合放真正需要的靜態資源，**不要把建置產物（如 APK 檔）暫時放進去**（見下方「⚠️ 已知教訓」）。

### `electron/` 與 `build/` 的關聯

`electron/`（進入點程式碼）與 `build/`（electron-builder 設定來源，如圖示、安裝程式腳本）是配對出現的：有 `electron/` 就會有 `build/`，兩者只存在於同時支援桌面版的 myStock、TripleTown，JournalApp、myLife 兩者都沒有。

### App 圖示：`build-apk.cmd` 是否重新產生

| 專案 | 圖示來源 | `build-apk.cmd` 會跑 `capacitor-assets generate`？ |
|------|----------|:---:|
| JournalApp | `resources/icon.png` | ❌（換圖示後需手動執行） |
| myStock | `assets/icon.png` | ❌（換圖示後需手動執行；`@capacitor/assets` 未列入 devDependencies，`npx` 會臨時下載） |
| TripleTown | `build/icon.png`（僅 Windows 版；依 TripleTown `CLAUDE.md`，Android 仍為 Capacitor 預設圖示） | ❌ |
| myLife | `assets/icon.png` | ✅ |

`npx cap sync` **只同步網頁資產，從不碰圖示**。沒有在打包流程裡重新產生的專案，換了來源圖檔之後 APK 上的圖示不會變——myLife 曾因此踩到（2026-09-22：來源圖 9/20 已換，產出的圖示仍停在 9/17），之後才把這一步加進 `build-apk.cmd`。其他三個專案換圖示時要記得手動執行 `npx capacitor-assets generate --android`。

### ⚠️ 已知教訓：不要把建置產物複製進 `public/`

2026-07 於 JournalApp 開發過程中，曾為了方便手機下載側載安裝，把打包好的 APK 複製進 `public/JournalApp-v1.0-debug.apk`。但如上所述，`public/` 內容會被 `vite build` 複製進 `dist/`，`npx cap sync android` 又把 `dist/` 整包複製進**下一次**要打包的 Android app 資產——等於「上一版 APK 被包進這一版 APK」，每 build 一次體積就疊加一層舊 APK，實測從 26MB 一路長到 41MB 才被發現。

**修法**（已套用於 JournalApp）：`vite.config.js` 新增一個僅 `vite dev` 生效的自訂 middleware，直接從 `release/` 資料夾讀檔提供 `/release/*.apk` 下載路徑，完全不經過 `public/`／`dist/`。

**檢查過 myStock、TripleTown、myLife 的建置腳本（`build-apk.cmd`）與 `public/` 資料夾，三者皆無此問題**——`build-apk.cmd` 只把 APK 複製到 `release/`，從未寫入 `public/`（TripleTown、myLife 根本沒有 `public/`）；這是 JournalApp 那次開發過程中的臨時操作失誤，不是範本腳本本身的通病。**日後新專案要比照 Capacitor + 手機下載側載安裝流程時，記得直接沿用 JournalApp 這個 middleware 寫法，不要重蹈覆轍。**
